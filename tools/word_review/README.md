# Word review

`corpuses/glypoon.txt` (the list daily puzzles are built from) is generated by
[`../build_corpus.py`](../build_corpus.py) in two stages. This replaces the old
`script.ipynb` pipeline, which filtered COED with phrase-matched blocklists and then
intersected it with an external word list (`words58k.txt`) as a "commonness" test.

## Stage 1: rules (code)

Every lowercase, letters-only COED headword of 3–10 letters is checked against
[`RULES.md`](../../RULES.md) using its own dictionary entry. Rejects, with reasons, are in
`rule_rejects.tsv`.

| Rule | How it's detected |
|---|---|
| No plurals, verb inflections, or forms only noted under another word | The entry has no part-of-speech label of its own; it only points at another headword (e.g. `hands → hand`, `foretold: past of foretell`, `worried: [as adjective worried]` under "worry") |
| No abbreviations, symbols, prefixes, suffixes, combining forms | Every part-of-speech label is one of these |
| No comparatives/superlatives as adjective forms | Entry starts "superlative of" / "comparative of" and is only adjective/adverb (`driest`, `furthest`); `better`, `worst` etc. have noun/verb senses and stay |
| No adverbs ending in -ly | Ends in -ly and every label is an adverb (`daily`, `lovely` are adjectives and stay) |

Allowed: verb forms with their own entry and part of speech (`given`, `broken`, `said`), words
COED lists only as plural nouns (`scissors`, `spaghetti`), contractions written as one word
(`cannot`). `lots` (adverb) is added by hand because the dictionary files have no headword for it.

## Stage 2: review (by hand)

Every word that passes the rules was reviewed and given a decision in `review.tsv`:

| | Meaning | In corpus? |
|---|---|---|
| `A` | Well known, or obscure enough that finding it makes a player feel smart (tocsin, surd, quorate, sylph) | yes |
| `B` | Specialist jargon, proper-noun look-alikes (york, henry), regional slang, rare spelling variants | no |
| `O` | Offensive: slurs, vulgar words, and words whose best-known sense is either | no |

The aim was to keep today's experience, including its level of rareness: the review replaces
`words58k` as the "is this fair?" test. Common alternative spellings are both kept (`likable` /
`likeable`, `donut` / `doughnut`) so a player's normal spelling isn't rejected.

Rareness was checked against word frequency (`wordfreq` Zipf scores, where about 3 is a typical
word and under 2 is rare). The old and new lists have the same share of rare words, with the new
list leaning slightly more obscure. Rarer words were only kept if they were already in the old
list; words added that the old list didn't have are all well known.

| | Rarer than 2.0 | Rarer than 1.5 |
|---|---|---|
| Old list | 11.0% | 3.4% |
| New list | 11.7% | 3.3% |

## Result

| | Words |
|---|---|
| Old list | 20,711 |
| New list | 21,839 |
| Removed | 1,560: 932 by rule, 609 jargon/look-alikes/variants (`B`), 19 offensive (`O`) |
| Added | 2,687 well-known words the old list was missing (cookie, daily, people, scissors, traipse, workaround) |

- **Removed by rule:** hands, groceries, greetings, antennae, bade, worried, thatched,
  committed, appalling.
- **Removed as `B`:** york, henry, oxford (proper-noun look-alikes), mediaeval, hullo (rare
  variants), and deep jargon a player couldn't reasonably guess (aldrin, epicycloid, microfarad,
  effluxion).
- **Removed as offensive:** spastic, retard, squaw, midget, poof, golliwog, kinky.

Puzzle generation still works on every day of the week. In a simulation, a random starting word
gives a valid puzzle 59–74% of the time (it was 62–73%), and the generator retries until it gets
one.

## Changing a decision

Edit the word's line in `review.tsv`, then run:

```sh
cd tools && python3 build_corpus.py
```

`build_corpus.py --candidates FILE` lists every candidate with a short gloss, for example to
review new entries after a dictionary update. The build refuses to run if any candidate has no
decision.
